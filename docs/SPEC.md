# Worm Rush — ТЗ и роадмап playable ad (Unity, 2D)

**Цель.** Показать Azur Games, что я закрываю production playable end to end: от задачи до билда, в Unity, через Claude Code. Это портфолио-кейс под вакансию «Middle Vibecoder (Playable Ads)».

**Референс жанра.** io-snake в духе WormsZone.io, их хита №1. Используем только жанр и механику. Их название, логотип, персонажей и стиль не копируем. Рабочее название — *Worm Rush*.

**Готовый прототип логики.** `reference/worm-rush-playable.html` (12 КБ, чистый JS). Он служит эталоном поведения и таймингов: если сомневаешься, как должна работать механика, смотри туда.

## 1. Продукт: что видит игрок

Длительность 20–30 секунд. Ориентация — портрет 9:16, ландшафт тоже должен корректно работать.

| Время | Бит | Что происходит | Зачем |
|---|---|---|---|
| 0–3 с | **Hook + туториал** | Червяк медленно кружит, внизу рука-подсказка «DRAG TO MOVE» | Понятно за 1 секунду, что делать |
| 3–10 с | **Рост** | Игрок ест еду: еда притягивается, звук нарастает с комбо, растёт счётчик длины | Быстрая награда, ощущение прогресса |
| ~7 с | **Завязка** | Надпись «Block their path!», маленький бот идёт наперерез | Подготовка вау-момента |
| 8–15 с | **Кульминация** | Бот врезается в тело игрока и взрывается едой. «+1 KILL!», тряска камеры | Главная эмоция ролика |
| +1.8 с / 25 с / смерть | **End card** | «AWESOME!» или «SO CLOSE!», пульсирующая кнопка PLAY NOW, тап в любом месте ведёт в стор | Конверсия |

**Постоянный CTA** — маленькая кнопка внизу с первой секунды. Это требование части сетей.

## 2. Механики (спецификация)

- **Арена** — круг радиусом 1000 юнитов. Игрок упирается в край, бот на краю погибает.
- **Червяк** — цепочка сегментов с фиксированным шагом. Голова движется со скоростью `speed`, поворачивает к цели с ограниченной угловой скоростью (~4.2 рад/с). Каждый сегмент тянется за предыдущим. Радиус растёт с длиной.
- **Управление.** Червяк поворачивает в сторону пальца относительно центра экрана, игрок всегда в центре. Отпустил палец — сохраняется последнее направление.
- **Еда** — около 380 точек одновременно, при поедании досыпается новая. Обычная еда даёт 1, остатки погибшего червяка — 3. Вблизи головы игрока еда притягивается (магнит).
- **Смерть.** Голова касается тела другого червяка (кроме первых 2 сегментов) — червяк погибает и рассыпается едой своего цвета.
- **Боты** (5 шт.). Выбирают ближайшую еду из случайной выборки, раз в 0.8–2 с меняют цель, от края уходят к центру.
- **Скриптованная жертва.** Бот №0 через 4 с после первого тапа нацеливается на середину тела игрока. Так кульминация гарантированно случается, но выглядит естественно.
- **До первого тапа** игрок неуязвим.

## 3. Архитектура

Тот же принцип, что в моём match-3: **ядро на чистом C# без Unity**, Unity отвечает только за отображение.

```
Assets/_Project/
  Core/            (asmdef без UnityEngine)
    WormSim.cs           — шаг симуляции, миры, спавн
    Worm.cs, Food.cs     — данные
    SpatialHash.cs       — коллизии и еда без физики
    BotBrain.cs          — ИИ ботов + скрипт жертвы
    SimEvents.cs         — Ate, Killed, PlayerDied (события для view)
  Flow/
    PlayableFlow.cs      — стейт-машина: Intro → Tutorial → Play → Climax → EndCard
  View/
    WormRenderer.cs      — сегменты через Graphics.RenderMeshInstanced
    FoodRenderer.cs      — то же, один материал
    CameraFollow.cs, Juice.cs (shake, popups, particles из пула)
    HUD.cs, EndCard.cs
  Ad/
    IAdNetwork.cs        — OpenStore(), GameReady(), GameEnd()
    EditorAdNetwork.cs, WebAdNetwork.cs (MRAID/window.open через .jslib)
  Config/
    PlayableConfig.asset — ScriptableObject: тайминги, скорости, цвета, тексты, ссылки
  Tests/EditMode/        — тесты ядра
```

**Ключевые решения.**
- **Без физики.** Коллизии — свой spatial hash. Модули Physics и Physics2D отключаются, билд становится легче.
- **Без GameObject на сегмент.** Все сегменты и еда рисуются инстансингом, по 1–2 draw call на тип.
- **Всё, что продюсер захочет поменять, лежит в `PlayableConfig`.** Плюс переопределение через URL-параметры в веб-билде: `?duration=20&victimDelay=3&cta=INSTALL&theme=1`. Это прямой ответ на пункт вакансии «инструменты для быстрых изменений в билдах», и это стоит показать отдельно.
- **`IAdNetwork`** изолирует специфику сетей: MRAID у одних, `ExitApi` у Google, свои колбэки у Mintegral. Добавить сеть = добавить один класс.

## 4. Нефункциональные требования

| Параметр | Цель |
|---|---|
| FPS | стабильные 60 на среднем Android |
| Draw calls | ≤ 15 |
| Сборка демо | Unity Web, Brotli, IL2CPP Code Optimization = Size, Managed Stripping = High, отключены неиспользуемые модули |
| Вес | минимальный, какой даёт Unity Web. Зафиксировать цифру в README |
| Внешние запросы | нет, все ассеты внутри |
| Ассеты | свои или сгенерированные: один атлас спрайтов, один шрифт с subset латиницы |

**Честная оговорка, которую надо проговорить на собеседовании.** Чистый Unity Web-билд весит больше лимитов рекламных сетей (обычно единицы МБ). В продакшене playable из Unity собирают через Luna Playworks или аналоги, которые конвертируют проект в лёгкий HTML5. Мой Unity-билд — это демо архитектуры и пайплайна. HTML-версия на 12 КБ показывает, что я понимаю реальные ограничения. Уточнить у Azur, какой конвертер у них в пайплайне.

## 5. Роадмап

Каждый этап заканчивается рабочим билдом и коммитом. Оценки даны с учётом Claude Code.

| # | Этап | Результат / критерий приёмки | Оценка |
|---|---|---|---|
| 0 | **Сетап** | Unity 6, 2D-проект, структура папок, asmdef, GitHub-репо, `CLAUDE.md` с правилами (Core без UnityEngine, тесты на ядро, конфиг вместо хардкода) | 0.5 ч |
| 1 | **Ядро симуляции** | `WormSim` двигает червяков, ест еду, считает смерти. EditMode-тесты: рост, коллизия, смерть на краю, скрипт жертвы срабатывает | 1.5 ч |
| 2 | **Отображение + управление** | Червяк и еда видны и рисуются инстансингом, камера следует, палец/мышь управляют. 60 FPS в редакторе | 1.5 ч |
| 3 | **Боты и коллизии** | 5 ботов, жертва гарантированно погибает об игрока за 8–15 с в 9 из 10 прогонов | 1 ч |
| 4 | **Flow + end card** | Стейт-машина, рука-туториал, «Block their path!», end card по трём условиям, CTA вызывает `IAdNetwork.OpenStore` | 1.5 ч |
| — | **MVP — можно показывать** | Полный 25-секундный цикл в Web-билде | **≈ 6 ч** |
| 5 | **Juice** | Тряска, попапы «+1 KILL», частицы из пула, звуки с нарастанием, пульс кнопки | 1 ч |
| 6 | **Варианты креатива** | `PlayableConfig` + URL-параметры, 2–3 пресета (другая палитра, короче таймер, другой текст CTA) | 1 ч |
| 7 | **Оптимизация и деплой** | Чистка модулей, замер веса и draw calls, деплой на Cloudflare Workers рядом с match-3. Цифры — в README | 1 ч |

Если к звонку готов MVP — отлично, это сильный козырь. Не жертвуй сном и подготовкой ответов ради этапов 5–8.

## 6. Процесс

Правила работы и порядок этапа описаны в `CLAUDE.md`, журнал передачи между сессиями ведётся в `docs/PROGRESS.md`.
Схема такая: один этап — одна новая сессия, одна ветка и один PR. Ревью и мёрж делает Егор.
Логику ядра можно тестировать без Unity: для этого есть проект `CoreTests/` (.NET + NUnit), он компилирует исходники из `Assets/_Project/Core`. Создаётся на этапе 1.
